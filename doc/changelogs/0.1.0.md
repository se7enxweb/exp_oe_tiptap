# exp_oe_tiptap 0.1.0

The first release: a Tiptap based online editor for ezxmltext fields in Exponential 6, next to the Online Editor
(ezoe), switchable on the fly, with optional AI commands that keep the structure of the text. Compare-ready: ezoe
stays the default editor until the round trip is green on your own content.

## Added

- Added: The input handler `expOETiptapXMLInput`, which extends ezoe's `eZOEXMLInput` and changes nothing but the
  edit template. Content stays ezxmltext: ezoe still turns ezxml into its editor HTML and parses that HTML back, only
  the editor in the middle is TinyMCE or Tiptap. `extension.xml` declares that it extends ezoe, so its input handler
  alias wins in any `ActiveExtensions` order.
- Added: The switch between the two editors. A button below every XML text field ("Switch to Tiptap", "Switch to
  Online Editor (TinyMCE)") stores the draft first, like ezoe's "Disable editor", and brings the form back with the
  other editor and the text kept. The choice is a preference of the user (`exp_oe_editor`); `[EditorSettings]
  DefaultEditor` gives the default per siteaccess, `AllowSwitch` and the policy `exp_oe_tiptap/switch` decide who may
  switch. The view `exp_oe_tiptap/switch` sets the preference outside the edit form, with a form token check and a
  redirect limited to this site.
- Added: The content mapping. Tiptap's schema mirrors ezoe's editor HTML one to one: paragraphs with alignment and
  classes, headers with anchors, lines, literals, lists, tables with header cells, spans, widths and custom
  attributes, links to URLs, objects, nodes and anchors with target, title, class, view and id, block and inline
  embeds of objects and images, block, inline and image custom tags, and every `customattributes` value. What one
  editor writes the other reads, and the stored XML is the same. Details: [content-mapping.md](../content-mapping.md).
- Added: The editor in ezoe's look: toolbar from ezoe's layout settings, path bar, word count, resize handle, full
  screen, keyboard shortcuts, paste cleanup, and dialogs for links, anchors, images and objects (search, browse,
  bookmarks, upload), files, custom tags, tables and cells, special characters and help.
- Added: The AI assistant, off by default: improve, shorten, extend, fix spelling and grammar, translate, summarise
  and continue writing, on the selection or the whole text. The browser only calls the ezjscore function
  `expoetiptap::ai` of this installation; the provider (any OpenAI compatible endpoint, Anthropic, or a class of
  your own) and its key stay on the server. Needs `[AISettings] Enabled=true` and the policy `exp_oe_tiptap/ai`.
- Added: Structure keeping for the AI. The text is sent as a markup of text, simple tags and numbered placeholders
  for embeds, images, custom tags, anchors, tables and literals, without ids or URLs. The answer is checked (every
  placeholder back exactly once, every link kept) and rebuilt with the original nodes, so a rewrite changes wording
  only. An answer that loses or invents items is asked for once more with a stricter instruction; if it still fails,
  the preview warns and offers Insert below and Keep original. The preview is a word diff with the items as chips.
- Added: Translations: every text of the editor, the switch and the AI assistant (209 texts) in the context
  `extension/exp_oe_tiptap`, with a German translation and an untranslated template. Error messages of the AI
  assistant reach the editor translated.
- Added: Tests without database or network: PHP unit tests for the editor choice, the switch view, the metadata,
  the input handler, the translations and the AI hooks with a fake provider; JavaScript tests for the schema, the
  editor, the dialogs and the AI panel; a round trip ezxml -> ezoe HTML -> Tiptap -> ezoe HTML -> ezxml over 63
  fixtures (50 from real content with personal data replaced, 13 synthetic), run against a copy of the database.
  The real-content fixtures follow the demo content after it was brought into ezoe's dialect: 6 of 63 are lossy
  against the original ezxml (27 before), all of them in ezoe alone as well.
- Added: Documentation: installation, usage, configuration, architecture, content mapping, AI hooks, extending and
  maintenance.

## Known limits

- Not for production yet: ezoe stays the default editor. Run the round trip on your own content first.
- Tiptap loses nothing that ezoe keeps (63 of 63 fixtures identical or equal to ezoe alone), but content outside
  ezoe's dialect is lost in either editor: lists, embeds or headers directly under a section, as imported content
  often has, are dropped by ezoe's own conversion when the object is saved.
- The nesting order of inline marks can change (`<link><strong>` versus `<strong><link>`); the output renders the
  same.
- An embed inserted in the editor shows a preview only when the dialog supplies one; the preview of existing embeds
  is the one the server rendered when the form was loaded.
- The AI assistant works on one table cell or on text outside a table; a selection across cells is refused, and a
  whole document keeps its tables unchanged (a table is one placeholder). Summaries and continued text hold no
  embeds, custom tags or tables.
- No collaboration, comments or track changes, and none of Tiptap's paid Pro extensions.
- The AI provider, its cost and whether content may leave the server are the site owner's decision; nothing is
  enabled by default.

## Requirements

Exponential 6.0.14 or later, PHP 8.0 or later, ezoe, ezjscore and ezformtoken active; PHP curl for the AI commands.
Built with Tiptap 3.31.4 (MIT License); the built bundle is committed, so a site does not need Node.js.
